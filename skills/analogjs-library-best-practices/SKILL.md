# AnalogJS Library Best Practices

Use this skill to make AnalogJS libraries feel intentional instead of like a folder tree won a coin toss.

## Start With Library Shape

Classify the work before changing structure:

- **UI component library** — reusable components/services, no routes or backend
- **Content/documentation library** — markdown content under `src/content`
- **Fullstack feature** — pages plus backend API
- **API service library** — backend-first, no pages
- **Shared utility library** — pure TypeScript helpers and types

Choose the smallest shape that fits. Add `pages`, `api`, or `content` only when the feature genuinely needs them.

## Read References Deliberately

Read `references/ARCHITECTURE.md` first for any structural work.

Then load references selectively:

- Read `references/API-DESIGN.md` when touching `src/backend`, `src/models`, or cross-boundary contracts.
- Read `references/TESTING.md` when adding or changing tests.
- Read `references/PITFALLS.md` before finalizing or when something feels “almost right.”

## Apply Core Conventions

- Keep route files in `src/pages/` as thin wrappers with `default` exports.
- Put page logic and feature UI in `src/lib/pages/`.
- Put reusable UI in `src/lib/components/`.
- Put business logic and data orchestration in `src/lib/services/`.
- Put shared contracts in `src/models/`; prefer Zod when data crosses server/client boundaries.
- Keep server-only code under `src/backend/` and out of the main frontend barrel.
- Prefer REST handlers under `src/backend/api/routes/api/<library>/`.
- Treat tRPC as **legacy** and include it only when the user explicitly asks for it.

## Follow Angular + AnalogJS Patterns

- Use standalone Angular APIs.
- Prefer signals, `resource()`, and `inject()`.
- Use modern control flow (`@if`, `@for`, `@switch`).
- Avoid NgModules, `CommonModule`, and `RouterModule` in new code.
- Keep filenames in kebab-case; keep public exports intentional and minimal.

## Wire Consumer Apps Correctly

When a library contributes pages or backend routes to an app, verify the consuming app is wired for it:

- `tsconfig.base.json` path aliases
- `vite.config.*` `additionalPagesDirs` / `additionalAPIDirs`
- Tailwind source scanning when library templates use utility classes
- `ssr.noExternal` when SSR dependencies require bundling
